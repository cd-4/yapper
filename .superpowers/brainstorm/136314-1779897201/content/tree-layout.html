Tree layout options

How should test results be grouped and structured?

auth.yaml  1 failed  2 passed
✓ login-test
✗ token-refresh 12ms
✗ status 401 — expected 200
✓ response has token field
↗ go to test
✓ logout-test
users.yaml  1 passed
✓ get-user-profile

A — File-grouped

Tests nest under their source file. Files show a pass/fail count. Matches how tests are organized on disk.

✗ Failed (1)
✗ token-refresh auth.yaml
✗ status 401 — expected 200
✓ response has token field
↗ go to test
✓ Passed (3)
login-test auth.yaml
logout-test auth.yaml
get-user-profile users.yaml

B — Pass/fail split

Failed tests surface at the top, passed tests collapsed below. Prioritizes failures — fastest path to what's broken.

auth.yaml
✗ token-refresh
✗ status 401 — expected 200
✓ response has token field
↗ go to test ↺ re-run
✓ login-test
✓ logout-test
users.yaml
✓ get-user-profile
3/4 passed · 48ms

C — File-grouped + re-run

Like A but with a re-run button on each test. Pairs with the navigate action for a quick fix→re-run loop.
